# Книжная полка (Book Shelf)

Веб-приложение для учёта прочитанных книг с разделением на клиентскую часть (Vanilla JS), серверную часть (REST API на чистом Node.js) и надёжное реляционное хранилище данных (**PostgreSQL**).

---

##  Пошаговое руководство по запуску с нуля

### Шаг 1. Проверка и установка Node.js
Для работы сервера необходима среда выполнения **Node.js (версии 22.9.0 или новее)**.
1. Проверьте, установлен ли Node.js на компьютере. В терминале выполните:
   ```bash
   node -v
   ```
   * Если отобразилась версия (`v22.9.0` или выше) — всё готово.
   * Если команда не найдена или версия ниже — скачайте и установите актуальную версию Node.js с официального сайта: [nodejs.org](https://nodejs.org/).

---

### Шаг 2. Проверка и установка PostgreSQL
Для хранения данных используется реляционная СУБД **PostgreSQL**.

1. Убедитесь, что сервер PostgreSQL установлен и служба запущена на стандартном порту `5432`.
2. Если PostgreSQL ещё не установлен:
   * Скачайте установщик для вашей ОС с официального сайта: [postgresql.org/download](https://www.postgresql.org/download/).
   * При установке задайте пароль для суперпользователя `postgres` (запомните его).

---

### Шаг 3. Получение файлов проекта и установка зависимостей
1. Склонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone https://github.com/d0kus/book-shelf.git
   cd book-shelf
   ```
2. Установите необходимые зависимости (драйвер `pg` для работы с базой данных):
   ```bash
   npm install
   ```

---

### Шаг 4. Настройка переменных окружения (.env)
В корне проекта находится шаблон конфигурации `.env.example`.
1. Создайте в корне проекта файл `.env`, скопировав шаблон:
   * В Linux / macOS / Git Bash: `cp .env.example .env`
   * В Windows (CMD): `copy .env.example .env`
2. Откройте файл `.env` и укажите параметры подключения к PostgreSQL:
   ```env
   DB_HOST=localhost
   DB_PORT=5432
   DB_USER=book_shelf_user
   DB_PASSWORD=your_password_here
   DB_NAME=book_shelf
   DB_ADMIN_USER=postgres
   DB_ADMIN_PASSWORD=your_postgres_password_here
   ```
   * `DB_USER` / `DB_PASSWORD` — отдельная роль приложения с ограниченными правами (создаётся автоматически на следующем шаге; именно под ней работает сервер).
   * `DB_ADMIN_USER` / `DB_ADMIN_PASSWORD` — суперпользователь PostgreSQL (используется только при инициализации в Шаге 5 для создания базы, таблиц и роли).

---

### Шаг 5. Автоматическая инициализация базы данных и сидов
Для автоматического создания базы данных, роли приложения, таблиц и заполнения их тестовыми данными выполните команду:
```bash
npm run db:init
```
> **Что делает эта команда:**
> 1. Подключается под `DB_ADMIN_USER` к служебной базе `postgres`.
> 2. Проверяет наличие базы данных `book_shelf` и при необходимости создаёт её.
> 3. Создаёт отдельную роль `DB_USER` (по умолчанию `book_shelf_user`) или обновляет её пароль через `ALTER ROLE`, если роль уже существует.
> 4. Переподключается к `book_shelf`, создаёт таблицы `books` и `notes` (со связью `ON DELETE CASCADE`) и индекс `idx_notes_book_id` на внешний ключ `notes(book_id)`.
> 5. Наполняет таблицы начальными демо-книгами и заметками к ним (Seed data).
> 6. Выдаёт роли `DB_USER` минимально необходимые права (`CONNECT`, `USAGE ON SCHEMA public`, `SELECT, INSERT, UPDATE, DELETE` на таблицы и права `USAGE, SELECT` на последовательности `SERIAL`).

> **Внимание!** при каждом запуске команда `npm run db:init` выполняет `DROP TABLE IF EXISTS books, notes CASCADE` — **она полностью удаляет все существующие таблицы и ваши данные**, возвращая базу к исходным демо-книгам. Не запускайте её повторно, если хотите сохранить текущие записи.

##  REST API

Базовый URL: `http://localhost:3000`

### Модели данных

#### Книга (Book) с вложенными заметками
```json
{
  "id": 1,
  "title": "1984",
  "author": "George Orwell",
  "status": "read",
  "rating": 5,
  "created_at": "2026-11-20T10:00:00.000Z",
  "notes": [
    {
      "id": 1,
      "text": "Сильное произведение о тоталитаризме.",
      "created_at": "2026-11-20T10:05:00.000Z"
    }
  ]
}
```

#### Заметка (Note)
```json
{
  "id": 1,
  "book_id": 1,
  "text": "Перечитать главу 3",
  "created_at": "2026-11-20T10:05:00.000Z"
}
```

---

### Эндпоинты: Книги (`/books`)

| Метод | URL | Описание | Тело запроса | Успешный ответ | Возможные ошибки |
|---|---|---|---|---|---|
| `GET` | `/books` | Получение списка книг с вложенными заметками. Query-фильтры: `id`, `title`, `author`, `status`. | — | `200 OK`, массив объектов книг | `400`, `500` |
| `POST` | `/books` | Создание новой книги. `title` и `author` — до 255 символов (`author` и `rating` необязательны). | `{"title": "...", "author": "...", "status": "want"}` | `201 Created`, объект созданной книги (с `notes: []`) | `400`, `500` |
| `PATCH` | `/books/:id` | Частичное обновление книги. При статусе не `"read"` оценка сбрасывается в `null`. | `{"status": "read", "rating": 5}` | `200 OK`, обновлённая запись книги (без поля `notes`) | `400`, `404`, `500` |
| `DELETE` | `/books/:id` | Удаление книги. **Каскадно удаляет все связанные заметки**. | — | `200 OK`, `{"message": "Книга успешно удалена"}` | `404`, `500` |

---

### Эндпоинты: Заметки (`/notes`)
| Метод | URL | Описание | Тело запроса | Успешный ответ | Возможные ошибки |
|---|---|---|---|---|---|
| `POST` | `/books/:id/notes` | Добавление новой заметки к книге с указанным `id`. | `{"text": "Текст заметки"}` | `201 Created`, объект созданной заметки | `400`, `404`, `500` |
| `PATCH` | `/notes/:id` | Редактирование текста существующей заметки по её `id`. | `{"text": "Обновлённый текст"}` | `200 OK`, объект обновлённой заметки | `400`, `404`, `500` |
| `DELETE` | `/notes/:id` | Удаление заметки по её `id`. | — | `200 OK`, `{"message": "Заметка успешно удалена"}` | `404`, `500` |

---

### Формат и коды ошибок API
При любой ошибке сервер возвращает JSON вида:
```json
{
  "error": "Текст ошибки"
}
```
* **`400 Bad Request`** — некорректный URL или JSON в теле запроса; тело запроса не является объектом; некорректный ID в query (`?id=abc`); пустое название книги или текст заметки; `title` или `author` длиннее 255 символов; недопустимый `status` (`want` / `reading` / `read`) или `rating` (не целое число от 1 до 5).
* **`404 Not Found`** — книга (`"Книга не найдена"`), заметка (`"Заметка не найдена"`) или маршрут (`"Страница не найдена"`) не существуют (в том числе при передаче нечислового ID или лишних сегментов пути, например `/books/1/notes` для `DELETE`).
* **`500 Internal Server Error`** — ошибка при выполнении запроса к PostgreSQL (`"Внутренняя ошибка сервера"`).

---

### CORS и Preflight
Сервер поддерживает CORS для всех доменов (`*`), обрабатывает Preflight-запросы `OPTIONS` и возвращает статус `204 No Content` со списком разрешённых методов: `GET, POST, PATCH, DELETE, OPTIONS`.

| 5 | Смена статуса и сброс оценки | Перевод книги из «Прочитано» в «Читаю» | `PATCH /books/:id`, статус `reading`, рейтинг в БД сбрасывается в `null` | Звёзды деактивированы, рейтинг сброшен |
| 6 | Добавление заметки к книге | Ввод текста в поле заметки карточки и клик «Добавить» | Запрос `POST /books/:id/notes`, статус `201`, заметка появляется вверху списка карточки | Заметка сохранена в таблице `notes` с текущим timestamp |
| 7 | Редактирование заметки | Клик на кнопку «Редактировать» у заметки, ввод нового текста в диалоге | Запрос `PATCH /notes/:id` с новым текстом, статус `200` | Текст заметки обновлён в БД и на экране без перезагрузки всей страницы |
| 8 | Отмена редактирования заметки | Клик «Отмена» или отправка того же самого текста | Запрос на сервер не отправляется | Никаких лишних сетевых вызовов, текст прежний |
| 9 | Удаление отдельной заметки | Клик по кнопке «Удалить» у заметки и подтверждение в `confirm` | Запрос `DELETE /notes/:id`, статус `200` | Заметка удалена из БД и исчезает из DOM |
| 10 | Каскадное удаление книги | Удаление книги, у которой есть несколько заметок | Запрос `DELETE /books/:id`. Срабатывает правило `ON DELETE CASCADE` | Книга удалена, все связанные заметки автоматически удалены из БД |
| 11 | Персистентность данных (PostgreSQL) | Добавление книги и заметок, остановка сервера (`Ctrl+C`), повторный `npm start` и F5 | Все созданные данные сохраняются в PostgreSQL и не теряются | Полная сохранность данных после перезапуска |

| 16 | Работа под отдельной ролью БД | Запуск `npm start` от роли `book_shelf_user` (с правами без `DROP`/`ALTER`) | Все CRUD-операции работают штатно без использования суперпользователя `postgres` | Все запросы к книгам и заметкам выполняются успешно |
